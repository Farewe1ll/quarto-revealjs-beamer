## 复核结论与证据边界

规划编制时，基线实现与上一轮复核时相同，并再次核对了对应源码、配置和探针结果。此前在同一基线运行的完整 `npm test` 通过；以下缺陷来自额外探针，说明当时套件缺少这些场景。规划编制时没有重跑套件；后续实施中的运行结果记录在文末。

| 事项 | 已确认事实与定位 | 对推进计划的影响 |
|:---|:---|:---|
| 引用子集排序 | [beamer.js](../_extensions/beamerslides/beamer.js) 的 `reorderReferences` 要求声明数等于渲染数。声明 `zulu,alpha,unused`、仅引用前两条时回退为 `alpha,zulu` | 必须修复，补能区分旧行为的测试 |
| 扫描顺序不可信 | [beamer.lua](../_extensions/beamerslides/beamer.lua) 的 `bib_entry_keys` 按行扫描。有效 BibTeX 的真实顺序为 `zulu,delta,alpha`，字段中的伪 header 与跨行真实 header 可使扫描得到 `zulu,alpha,delta`；JS 检查通过且没有告警 | 与子集支持一起处理，不能只删除数量检查 |
| 长文献页标题溢出 | JS 的 `decorateChrome` 中先 `paginateReferences`，后续才由 `measureFrameTitle` 更新标题高度。同一 13 条文献仍分成 9+4 条；首标题由 58px 增到 119px 时，首文献页正文溢出 5px，139px 时溢出 25px | 已确认标题几何缺陷；慢字体、图片的影响另行验证 |
| 渲染重试误分类 | [harness.mjs](../tests/lib/harness.mjs) 的 `withRenderRetries` 将普通退出码 2 的文档校验失败重试 3 次，日志称 Deno 崩溃，最终仍失败 | 改善分类和证据保留；没有证据表明语义断言失败会被重试成通过 |
| 模板复制范围 | 上一轮本地发布归档的模板安装、渲染成功，但模板复制了 `tests/`、`package*.json`、维护设计文档等开发文件 | 限定模板复制范围并补独立安装验证；不能描述为已证实的安装故障 |
| 最低版本声明 | [_extension.yml](../_extensions/beamerslides/_extension.yml) 声明 Quarto >=1.4.0，[CI](../.github/workflows/test.yml) 最低测试 1.4.557 | 是证据范围缺口，尚未证明 1.4.0 不兼容 |
| 还原度验证 | 当前截图基线来自本实现，缺少同内容的原版 Beamer 对照 | 补独立参照后再决定有无必要改变外观 |
| 混色说明 | [README](../README.md) 将误差部分归因于默认 Oklab 插值；实际样式明确使用 `color-mix(in srgb, ...)` | 修正文档依据，保留现有测试容差，不能由此推导出配色实现错误 |

已撤回或不属于缺陷修复的事项：章节页规则与单文件离线交付说明已补入文档；CambridgeUS 的红色结构色、黄色警示标题、通栏章节页及扁平列表是已记录的设计选择；badge 与滚动组合属于明确限制。文件长度说明维护成本，不能独自证明职责划分错误。原生 `::marker`、统一构建工具或拆分 JS 均需独立理由。

## 执行顺序与变更边界

每一阶段形成独立、可审阅的变更。缺陷测试与修复在同一交付中保持套件通过，并记录测试在旧实现上如何失败。阶段内部按依赖推进；不在同一 checkout 并行运行套件。

| 阶段 | 产出 | 依赖与优先级 | 完成门槛 |
|:---|:---|:---|:---|
| 1 | 可信的 declaration 排序与引用子集支持 | 优先；后续文献测量以正确条目顺序为基础 | 新场景旧实现失败、修复后通过；完整套件通过 |

## 阶段 1：文献排序

主要修改 [beamer.lua](../_extensions/beamerslides/beamer.lua)、[beamer.js](../_extensions/beamerslides/beamer.js)、[tests/fixtures](../tests/fixtures) 与 [run-tests.mjs](../tests/run-tests.mjs)，同步 README、R3 和已知缺陷状态。

1. 将子集失败与扫描误识别、漏识别相互抵消的输入变成永久回归场景。真实期望顺序按有效 BibTeX 输入独立确定，不从当前扫描结果生成。
2. 验证声明位置来源是否可靠，再建立已渲染条目的排序；未引用条目不要求出现在 HTML。检查跨文件顺序、重复 key、未匹配 key、读取失败及不支持的文献源。
3. 评估能识别顶层 entry 边界的有界扫描方案或可用解析能力，覆盖嵌套花括号、引号、多行字段、注释、忽略条目和跨行 header。以最小可验证方案为目标，不为排序引入未经验证的解析依赖。明确支持边界，不能把“数量与成员匹配”当作解析成功的证明。
4. 无法可靠取得声明顺序时保留 citeproc 序并给出准确诊断；`refs-order: citation` 的含义保持不变。正常的引用子集不告警，不改变引用链接和条目内容。

验收覆盖全量、子集、多文件、重复与未知 key、单独的伪 header、单独的跨行 header、两者抵消，以及排序后分页。每条真实文献仅出现一次，引用 id 与链接保持有效；运行完整 `npm test`。

## 阶段 2：文献分页与最终几何

主要修改 JS 的分页、标题测量与 Reveal 集成，以及文献 fixtures 和断言。先记录调用依赖，再验证候选方案；保留 L1 的首帧完整约束，不能未经验证就把所有分页移到 Reveal ready 之后。

1. 固化 119px 标题对应的溢出场景，并增加不溢出的相邻高度、超长标题阈值两侧、声明续页与自动续页。不能仅测试最终已进入滚动模式的标题。
2. 评估提前得到最终标题几何，或在几何确定后受控校正分页。选择方案时同时检查每页最终布局、隐藏祖先恢复、作者节点及 notes、条目唯一性、`uncounted`、chrome、Reveal 模型和当前页定位。
3. 如果需要重分页，明确原始条目与声明页的所有权、生成页的清理、重复事件的合并与稳定结束条件。不得重复追加页面、丢失条目或把测量输出反馈为 C3 的基准输入。异常路径恢复隐藏状态并保留诊断。
4. 用可控制延迟的字体与图片加载验证条目高度和可用区域的变化，分别记录是否出现问题、支持何种更新时机。只有验证需要时才引入相应更新机制；持续等待字体或无限重分页不作为方案。

验收要求：普通分页页在最终布局下容纳其条目，`item` 仍为上限；单条超高条目的滚动例外保留。覆盖 Madrid/CambridgeUS、h1/h2 文献标题、定制基准高度、4:3、resize、切页及打印；测试重复事件后页面数与条目归属稳定。完整套件包含初始化和全部文献回归。若已有图片按设计发生变化，逐张说明并审阅后才更新基线。

## 阶段 3：测试失败与重试

主要修改 [harness.mjs](../tests/lib/harness.mjs) 及必要的基础设施验证，不同时改变主题规则。

1. 让命令错误携带实际退出状态、信号、启动错误码和超时信息，避免把所有 SIGKILL 都解释成超时或把所有非零状态都解释成崩溃。
2. 对可识别的暂态失败建立有限重试规则；普通输入校验、文件缺失、权限等确定性失败直接报告。未分类错误不使用“Deno 崩溃”这样的确定归因。
3. 保留第一次及后续尝试的失败记录与重试理由，最终错误能追溯首次失败；整次操作重试仍须重建已清理的临时输入。
4. 用明确页面就绪条件替代单纯按 null/undefined 异常文本推断竞态。就绪条件满足后出现的运行时异常，以及语义断言失败，应直接报告；PDF 重试条件单独说明。

通过可控命令与页面场景检查普通失败尝试次数、已识别暂态失败、超时、重试耗尽、不同尝试错误证据和清理路径，避免测试只复述实现。清理失败不得跳过其他资源。完成后运行完整套件。

在仓库外的临时目录验证来自待交付变更的发布归档，避免测试意外找到仓库祖先的扩展或支持资源；不把忽略目录中的产物打进归档。

2. 明确模板所需文件清单：扩展、两种模板及其引用的示例和素材。新增根目录 `.quartoignore` 等复制规则，排除开发测试、依赖清单和维护文档，同时验证没有误排所需资源。
3. 在安装目录渲染 Madrid/CambridgeUS，检查资源相对路径、字体、公式、示例和文献。用户渲染不增加 Node 或构建步骤要求。

## 阶段 6：按收益拆分组织结构

先列出职责、共享状态和依赖方向；每次只做一项结构调整，与行为修复、依赖升级和外观变化分别交付。
